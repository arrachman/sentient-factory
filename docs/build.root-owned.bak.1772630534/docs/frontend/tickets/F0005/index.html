F0005: Create User Functionality

Overview​

Modal/form untuk membuat user baru dengan role assignment, email notifications, dan validation untuk admin dashboard.

Technical Context​

  • Location: apps/web-dashboard/components/admin/users/CreateUserModal/
  • Components: CreateUserModal, UserForm, RoleSelector
  • Technologies: React Hook Form, Zod, shadcn/ui, React Query
  • API Integration: POST /api/users, POST /api/users/invite

User Story​

As an administrator
I want to create new user accounts with specific roles
So that I can onboard new team members quickly and securely

Acceptance Criteria​

Functional Requirements​

  1. AC1: Modal form muncul ketika klik "Create User" button dari users list
  2. AC2: Form memiliki field: Name, Email, Password, Confirm Password, Role
  3. AC3: Form validation bekerja untuk semua required fields dengan real-time feedback
  4. AC4: Role dropdown menampilkan available roles dari system dengan search
  5. AC5: Email notification checkbox mengirim welcome email jika dicentang
  6. AC6: Generate random password button menghasilkan secure password
  7. AC7: Success toast muncul setelah user berhasil dibuat dengan details
  8. AC8: New user muncul di users list tanpa page refresh (optimistic update)

Technical Requirements​

  1. TR1: Form menggunakan React Hook Form dengan Zod validation
  2. TR2: Password strength meter dengan visual feedback
  3. TR3: Email format validation dengan debounce untuk duplicate check
  4. TR4: Role selector dengan virtual scrolling untuk banyak roles
  5. TR5: Auto-focus pada first field saat modal opens
  6. TR6: Keyboard navigation (Tab between fields, Esc to close)
  7. TR7: Loading states selama form submission
  8. TR8: Form persistence jika modal accidentally closed

Form Validation Schema​

const userFormSchema = z
  .object({
    name: z
      .string()
      .min(2, "Name must be at least 2 characters")
      .max(100, "Name too long"),
    email: z
      .string()
      .email("Invalid email address")
      .refine(async (email) => {
        // Check for duplicate email via API
        return !(await checkEmailExists(email));
      }, "Email already registered"),
    password: z
      .string()
      .min(8, "Password must be at least 8 characters")
      .max(50, "Password too long")
      .regex(/[A-Z]/, "Must contain uppercase letter")
      .regex(/[a-z]/, "Must contain lowercase letter")
      .regex(/[0-9]/, "Must contain number")
      .regex(/[^A-Za-z0-9]/, "Must contain special character"),
    confirmPassword: z.string(),
    roleId: z.string().uuid("Please select a role"),
    sendWelcomeEmail: z.boolean().default(false),
  })
  .refine((data) => data.password === data.confirmPassword, {
    message: "Passwords don't match",
    path: ["confirmPassword"],
  });

State Management​

// Create user hook:
const useCreateUser = () => {
  const queryClient = useQueryClient();

  return useMutation({
    mutationFn: (userData: CreateUserData) => api.users.create(userData),
    onMutate: async (newUser) => {
      // Cancel outgoing refetches
      await queryClient.cancelQueries({ queryKey: ["users"] });

      // Snapshot previous value
      const previousUsers = queryClient.getQueryData(["users"]);

      // Optimistically update
      queryClient.setQueryData(["users"], (old: any) => ({
        ...old,
        data: [newUser, ...old.data],
      }));

      return { previousUsers };
    },
    onError: (err, newUser, context) => {
      // Rollback on error
      queryClient.setQueryData(["users"], context?.previousUsers);
    },
    onSuccess: () => {
      // Invalidate and refetch
      queryClient.invalidateQueries({ queryKey: ["users"] });
    },
  });
};

Performance Requirements​

Response Times​

  • Modal open: < 100ms
  • Form validation: < 50ms per field
  • Email duplicate check: < 200ms
  • Form submission: < 1 second
  • Role dropdown load: < 300ms

Optimizations​

  1. Form Performance:

    • Debounced validation
    • Memoized form components
    • Lazy load role dropdown data
    • Optimistic updates

  2. API Performance:

    • Batch role fetching
    • Cached email checks
    • Efficient payloads
    • Retry logic untuk network issues

Accessibility Requirements​

WCAG 2.1 AA Compliance​

  1. Screen Reader Support:

    • Form field labels and descriptions
    • Error announcement
    • Success announcement
    • Modal open/close announcements

  2. Keyboard Navigation:

    • Tab through all form fields
    • Enter to submit, Esc to close
    • Arrow keys dalam dropdowns
    • Space to toggle checkboxes

  3. Focus Management:

    • Focus trapped dalam modal
    • Focus returns to trigger button setelah close
    • Focus pada first error field setelah submission fail

Security Considerations​

Password Security​

  1. Generation:

    • Cryptographically secure random generation
    • Minimum 12 characters default
    • Mix of character types
    • No dictionary words

  2. Transmission:

    • HTTPS required
    • Password never logged
    • Secure token transmission
    • Rate limiting pada submission

Data Privacy​

  1. Email Validation:
    • Generic error messages untuk duplicate emails
    • No email enumeration vulnerability
    • Rate limiting pada email checks
    • GDPR compliance

Error Handling​

Expected Errors​

  1. Validation Errors:

    • Invalid email format
    • Weak password
    • Password mismatch
    • Missing required fields

  2. API Errors:

    • Duplicate email
    • Invalid role
    • Email service failure
    • Network issues

Recovery Strategies​

  1. Validation Issues: Highlight fields dengan clear messages
  2. Duplicate Email: Suggest password reset atau different email
  3. Network Issues: Auto-retry dengan exponential backoff
  4. Service Issues: Fallback to create without email notification

Monitoring & Analytics​

Metrics to Track​

  1. Form Usage: Completion rate, drop-off points
  2. Error Rates: Validation errors by type
  3. Performance: Form load times, submission times
  4. User Behavior: Common role selections, email notification usage

Alerting​

  1. High Error Rates: > 10% submission failures
  2. Performance Issues: Form load > 500ms
  3. Security Alerts: Multiple failed submissions dari same IP
