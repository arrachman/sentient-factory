F0004: Users List Page

Overview​

Halaman untuk menampilkan daftar user dengan table, search, pagination, dan bulk operations untuk admin dashboard.

Technical Context​

  • Location: apps/web-dashboard/app/admin/users/
  • Components: UsersTable, Pagination, SearchBar, Filters
  • Technologies: Next.js 14, TanStack Table, shadcn/ui, Zustand
  • API Integration: GET /api/users, GET /api/users/stats

User Story​

As an administrator
I want to view and manage all system users in a list
So that I can efficiently administer user accounts and perform bulk actions

Acceptance Criteria​

Functional Requirements​

  1. AC1: Table menampilkan user data dengan columns: ID, Name, Email, Role, Status, Actions
  2. AC2: Pagination bekerja dengan options: 10, 25, 50, 100 items per page
  3. AC3: Search functionality filter users berdasarkan name, email, atau role
  4. AC4: Column sorting bekerja untuk semua sortable columns
  5. AC5: Bulk selection memungkinkan select/deselect multiple users
  6. AC6: Bulk actions (activate, deactivate, delete) bekerja untuk selected users
  7. AC7: Export to CSV/Excel functionality menghasilkan file dengan data yang benar
  8. AC8: Responsive design untuk mobile dan tablet dengan horizontal scroll

Technical Requirements​

  1. TR1: Server-side pagination dan filtering untuk performance
  2. TR2: Virtual scrolling atau infinite scroll untuk large datasets
  3. TR3: Type-safe table components dengan generics
  4. TR4: Skeleton loading states selama data fetching
  5. TR5: Error boundaries untuk failed data loads
  6. TR6: URL state synchronization untuk filters dan pagination
  7. TR7: Optimistic updates untuk quick actions
  8. TR8: Accessibility compliance (keyboard nav, screen readers)

Component Specifications​

1. Users Table Component​

// Features:
// - TanStack Table integration
// - Column definitions dengan customization
// - Row selection dengan checkboxes
// - Sorting handlers
// - Responsive design dengan horizontal scroll
// - Empty state display

2. Pagination Component​

// Features:
// - Server-side pagination controls
// - Page size selector
// - Current page indicator
// - Total items count
// - First/Last page buttons
// - Page number navigation

3. Search & Filters Component​

// Features:
- Debounced search input
- Filter by status (active, inactive, suspended)
- Filter by role (dropdown multi-select)
- Date range filter (created date)
- Clear all filters button

4. Bulk Actions Component​

// Features:
- Shows count of selected items
- Action buttons: Activate, Deactivate, Delete, Export
- Confirmation modals untuk destructive actions
- Loading states selama bulk operations
- Success/error feedback

State Management​

// Users store:
interface UsersStore {
  users: User[];
  selectedIds: string[];
  filters: UserFilters;
  pagination: PaginationState;
  isLoading: boolean;

  // Actions
  fetchUsers: () => Promise<void>;
  setFilters: (filters: Partial<UserFilters>) => void;
  setPagination: (pagination: PaginationState) => void;
  toggleSelection: (userId: string) => void;
  selectAll: () => void;
  clearSelection: () => void;
  performBulkAction: (action: BulkAction) => Promise<void>;
}

API Integration​

// API endpoints:
GET /api/users
Query params: page, limit, search, status, role, sortBy, sortOrder

GET /api/users/stats
Returns: total, active, inactive, suspended counts

POST /api/users/bulk-actions
Body: { action: 'activate' | 'deactivate' | 'delete', userIds: string[] }

Dependencies​

Frontend Dependencies​

  • F0003: Protected routes working
  • TanStack Table installed
  • shadcn/ui table components available
  • Zustand store setup

Backend Dependencies​

  • API endpoints for users data
  • Pagination support in API
  • Filtering and sorting support
  • Bulk actions API endpoints

Environment Dependencies​

  • API base URL configured
  • CORS configured
  • SSL certificates valid

Performance Requirements​

Load Times​

  • Initial page load: < 2 seconds
  • Table data fetch: < 1 second
  • Search/filter updates: < 500ms
  • Pagination changes: < 300ms

Optimizations​

  1. Data Fetching:

    • Server-side pagination
    • Query caching dengan React Query
    • Debounced search inputs
    • Optimistic updates

  2. Rendering:

    • Virtual scrolling untuk large tables
    • Memoized components
    • Lazy loaded components
    • Code splitting

Accessibility Requirements​

WCAG 2.1 AA Compliance​

  1. Keyboard Navigation:

    • Tab through table controls
    • Arrow keys untuk table navigation
    • Enter/Space untuk selection
    • Escape to clear selections

  2. Screen Reader Support:

    • Table aria labels dan descriptions
    • Row and column announcements
    • Selection state announcements
    • Pagination announcements

  3. Color Contrast:

    • Table text contrast
    • Selection highlight contrast
    • Button contrast ratios
    • Status badge colors

Error Handling​

Expected Errors​

  1. Data Fetch Errors:

    • Network failures
    • API errors
    • Timeouts
    • Invalid response format

  2. User Action Errors:

    • Bulk action failures
    • Export failures
    • Permission errors
    • Validation errors

Recovery Strategies​

  1. Data Issues: Retry dengan exponential backoff
  2. Action Issues: Show error dengan retry option
  3. Permission Issues: Redirect atau show unauthorized UI

Monitoring & Analytics​

Metrics to Track​

  1. Performance: Page load times, API response times
  2. Usage: Search usage, filter usage, export usage
  3. Errors: Failed loads, failed actions
  4. User Behavior: Common filters, typical page sizes

Alerting​

  1. Performance Alerts: Page load > 3s
  2. Error Alerts: Error rate > 1%
  3. Usage Alerts: Unusual export activity

Rollback Plan​

If Table System Fails​

  1. Minor Issues:

    • Disable specific features (export, bulk actions)
    • Fallback to basic table
    • Increase pagination limits

  2. Major Issues:

    • Disable users page completely
    • Deploy previous working version
    • Manual user management via API

Rollback Steps​

  1. Revert users page components
  2. Deploy simple table version
  3. Disable advanced features
  4. Communicate temporary limitations
