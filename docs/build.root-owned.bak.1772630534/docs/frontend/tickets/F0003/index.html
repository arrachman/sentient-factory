F0003: Protected Routes & Middleware

Overview​

Implementasi route protection dan authentication middleware untuk Next.js App Router dengan role-based access control.

Technical Context​

  • Location: apps/web-dashboard/middleware.ts, app/layout.tsx
  • Components: AuthProvider, ProtectedRoute, RoleGuard
  • Technologies: Next.js 14 Middleware, React Context, TypeScript
  • API Integration: GET /api/auth/verify

User Story​

As a system user
I want to access only authorized pages based on my role
So that I cannot accidentally or intentionally access restricted areas

Acceptance Criteria​

Functional Requirements​

  1. AC1: Next.js middleware memeriksa authentication status setiap request
  2. AC2: Unauthenticated users di-redirect ke login page
  3. AC3: Role-based route guards bekerja untuk semua protected routes
  4. AC4: Auth context/provider menyediakan user data ke seluruh app
  5. AC5: Custom hooks (useAuth, usePermissions) tersedia untuk components
  6. AC6: Public routes dapat diakses tanpa authentication
  7. AC7: Error handling untuk expired tokens dengan auto-logout
  8. AC8: Route protection works dengan SSR dan client-side navigation

Technical Requirements​

  1. TR1: Middleware menggunakan edge runtime
  2. TR2: Route matching dengan matcher configuration
  3. TR3: Token validation dengan API call atau JWT decode
  4. TR4: Role/permission checking dengan type safety
  5. TR5: Auth state synchronization antara middleware dan client
  6. TR6: Loading states selama auth verification
  7. TR7: Error boundaries untuk auth failures
  8. TR8: Performance optimized - minimal auth checks

Implementation Details​

File Structure​

apps/web-dashboard/
├── middleware.ts                    # Next.js middleware
├── app/
│   ├── layout.tsx                   # Root layout dengan AuthProvider
│   └── (protected)/
│       └── layout.tsx               # Protected routes layout
├── components/
│   └── auth/
│       ├── AuthProvider.tsx         # React Context provider
│       ├── ProtectedRoute.tsx       # Route guard component
│       └── RoleGuard.tsx            # Role-based guard
└── hooks/
    ├── useAuth.ts                   # Auth state hook
    ├── usePermissions.ts            # Permission check hook
    └── useRouteGuard.ts             # Route guard hook

Component Specifications​

1. Next.js Middleware (middleware.ts)​

// Features:
// - Edge runtime compatible
// - Public/private route configuration
// - Token validation dari cookies
// - Redirect ke login jika unauthenticated
// - Role-based path matching
// - Performance optimized (minimal checks)

2. Auth Provider Component​

// Features:
// - React Context untuk auth state
// - Token validation on mount
// - Auto-refresh token logic
// - Session timeout handling
// - Broadcast channel untuk multi-tab sync

3. Protected Route Component​

// Usage:
<ProtectedRoute
  requiredRoles={['admin', 'manager']}
  requiredPermissions={['users.view']}
  fallback={<Unauthorized />}
>
  <Dashboard />
</ProtectedRoute>

4. Custom Hooks​

// useAuth hook:
const { user, isLoading, error, login, logout } = useAuth();

// usePermissions hook:
const { hasRole, hasPermission, canAccess } = usePermissions();

// useRouteGuard hook:
const { isAuthorized, checkAccess } = useRouteGuard();

Route Configuration​

// route-config.ts
export const routes = {
  public: [
    "/auth/login",
    "/auth/register",
    "/auth/forgot-password",
    "/public/*",
  ],
  protected: {
    "/dashboard": ["admin", "manager", "user"],
    "/admin/users": ["admin"],
    "/admin/roles": ["admin"],
    "/profile": ["admin", "manager", "user"],
  },
  api: {
    public: ["/api/auth/*"],
    protected: ["/api/*"],
  },
};

Middleware Logic​

// Pseudo-code:
1. Check if path is in public routes → allow
2. Check for auth token in cookies
3. If no token → redirect to login
4. Validate token dengan API/decoding
5. Check user roles against route requirements
6. If unauthorized → redirect to unauthorized page
7. Add user info to request headers untuk API routes

Security Considerations​

Authentication Security​

  1. Token Validation:

    • Server-side validation untuk sensitive routes
    • Client-side validation untuk UX
    • Token refresh mechanism

  2. Route Protection:

    • Both server-side (middleware) dan client-side
    • Defense in depth approach
    • No sensitive data in client-side checks

  3. Error Handling:

    • Generic error messages
    • No information leakage
    • Secure logging

Performance Security​

  1. Rate Limiting:

    • Middleware rate limiting
    • API call debouncing
    • Cache auth checks where safe

  2. Resource Protection:

    • Prevent auth check loops
    • Timeout handling
    • Memory leak prevention

Performance Requirements​

Response Times​

  • Middleware auth check: < 50ms
  • Client-side auth check: < 10ms
  • Token validation API call: < 100ms
  • Route guard rendering: < 5ms

Optimizations​

  1. Caching:

    • Cache token validation results
    • Memoize auth state
    • Lazy load auth components

  2. Code Splitting:

    • Split middleware logic
    • Dynamic imports untuk auth components
    • Tree shaking unused code

Accessibility Requirements​

WCAG 2.1 AA Compliance​

  1. Screen Reader Support:

    • Auth state announcements
    • Route change announcements
    • Error announcements

  2. Keyboard Navigation:

    • Focus management setelah auth state changes
    • Keyboard shortcuts untuk auth actions
    • Escape to dismiss auth modals

  3. Loading States:

    • Loading announcements
    • Progress indicators
    • Timeout notifications

Error Handling​

Expected Errors​

  1. Auth Errors:

    • Token expired
    • Invalid token
    • Network errors during validation

  2. Permission Errors:

    • Insufficient roles
    • Missing permissions
    • Route configuration errors

Recovery Strategies​

  1. Token Issues: Auto-refresh atau redirect to login
  2. Network Issues: Retry dengan backoff
  3. Permission Issues: Show unauthorized UI dengan options

Monitoring & Analytics​

Metrics to Track​

  1. Auth Check Performance: Response times
  2. Error Rates: Auth failures by type
  3. User Access Patterns: Route access frequency
  4. Security Events: Unauthorized access attempts

Alerting​

  1. High Error Rates: > 5% auth failures
  2. Performance Degradation: Auth checks > 200ms
  3. Security Alerts: Multiple unauthorized attempts

Rollback Plan​

If Auth System Fails​

  1. Minor Issues:

    • Disable specific route guards
    • Fallback to basic auth checks
    • Temporary allow all access dengan warning

  2. Major Issues:

    • Disable middleware completely
    • Deploy previous working version
    • Manual auth state management

Rollback Steps​

  1. Revert middleware dan auth components
  2. Deploy version without route protection
  3. Implement basic cookie checks
  4. Notify users about temporary reduced security
